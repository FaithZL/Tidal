# 验收清单与证据要求

2026-10-21用户已批准真3D设计及A03数量处理（初始0、3棵各5段）；保留原49个ID，以下视觉标准扩展至当前3D。设计批准不代替最终视觉/摄像头真机签字，旧2D证据保存在历史报告。

同日追加入口要求：新浏览器默认模拟开启并自动进入正常流程，刷新新会话可直接演示；显式关闭/选择摄像头跨刷新保留手动，不自动申请设备或回到模拟；重置保留选择而不自动再开局。F01/F02的手动计划检查须先明确关闭模拟；自动默认/偏好覆盖由default-demo浏览器测试补充。其余计数、暂停、来源、隐私和真机标准不变。

版本：v1.0｜日期：2026-10-14。

这是待执行的测试计划，**本文件没有任何“已通过”的产品测试结果**。具体结果由开发者填写到`TEST_REPORT.md`。

原需求对应关系见`DEVELOPMENT_GUIDE.md`第1节。本文中的准确率、性能和重复测试次数都是建议验收目标，不是原文要求或已经测出的结果。

## 1. 三个交付等级

| 等级 | 通过条件 | 不能据此声称 |
|---|---|---|
| L1：键盘交互概念版 | T01–T04相关功能、规则与E2E通过；全流程可操作；明确模拟标签 | 真实摄像头已验证、最终美术已完成 |
| L2：指定环境摄像头互动版 | L1 + 真机姿态/动作链路、失效与恢复测试通过；持姿代理可用且明确标识 | 任意人/任意环境适用、真实负重检测、全身关节完全同步 |
| L3：可路演版 | L2 + 人工视觉/节奏批准、构建产物与本地断外网验证、彩排、关键产品默认值确认 | 已经是完整健身产品或完整农场经营游戏 |

原文A03数量冲突、A04“完全同步”、A06持握判定等未确认时，不能把满足临时方案等同于满足原文全部要求。用户可以接受明确降级，但应在报告中写明接受范围，不回填成原要求天然满足。

### 合成时间测试的精度口径

F07在测试夹具中给出精确起止时间，允许使用足够密集且满足`maxPoseGapMs`的样本，因此可做精确数值断言。真实摄像头有采样误差、标定确认延迟和漏帧，必须另测，不把单元测试精度直接宣传为真实测量精度。

## 4. 摄像头与动作验证

测试前记录单人、机位、光照、全身可见程度、视频尺寸、推理路径和标定参数。以下抽样仅用于指定演示环境，不代表泛化能力。

| ID | 操作/输入 | 建议验收标准 | 所属任务 |
|---|---|---|---|
| C01 | 人在镜头前移动肩腕髋膝 | 页面及游戏内PiP展示同一实时video/骨架，不复制track/Worker；模型/输入来源可确认；不是预录或随机数据 | T02/T09 |
| C02 | 按准备页完成站位和标定；再制造裁切/低置信度 | 有效输入才允许开始对应任务；失败有可理解提示，不用默认零坐标继续 | T06 |
| C03 | 指定演示者20次完整Chop；另20个不完整/停顿/抖动负例 | 建议完整动作至少19/20正确提交，负例误计不超过1/20；记录每个失败而非只记总数 | T07/T09 |
| C04 | 20次完整复合Load；另20个仅蹲/仅举/未复位等负例 | 同上；不能用纯深蹲次数代替复合动作识别结果 | T07/T09 |
| C05 | 持姿→放下→恢复至少5次 | 放下后不继续累计；UI最迟在300ms内显示非有效状态；恢复只计新有效样本区间 | T08/T09 |
| C06 | 持姿和放下姿态几乎相同 | 标定可分性检查拒绝自动Carry；明确人体姿态不能证明真实器械持握 | T08 |
| C07 | 整局真人操作并在每项中停顿一次 | 游戏角色阶段对应，完整流程可恢复，没有自动补做任务 | T09 |
| C08 | 人离开画面、另一人进入或姿态中心明显跳变 | 不承诺通用身份识别；当前动作不继续提交，提示重新准备；记录支持范围 | T06/T09 |

C03/C04阈值是草案建议。演示者不得为了通过测试而强行增加负重、动作幅度或速度；不舒适时停止，由产品/测试负责人重新确定演示动作和可用范围。

C05能证明的是被标定的两种姿态之间的响应，不能证明“空手但同姿态”会被识别为放下。L2/L3对此必须有可见限制说明和产品接受记录。
